# Teaching-oriented code review
1. Inspect only the relevant diff/files.
2. Identify bugs and security/correctness issues first; distinguish must-fix from optional improvements.
3. Give concise file/line references and explain why each issue matters.
4. Prefer hints or small patches over rewriting the whole feature unless asked.
5. End with up to three questions that check my understanding.
